# How an agent works an issue

1. **Hire**: the agent gets a station on the project's holodeck and a name. If the office is at its concurrency limit, they wait in the queue (⏳).
2. **Set up**: `~/.focus/repos/<owner>__<name>` holds one clone per repository. The agent gets a fresh `git worktree` of it on a new branch `focus/<issue>-<slug>-<id>`, so agents never step on each other.
3. **Work**: Claude Code runs in that worktree with the issue (title, body, labels, comments) as its task. It also gets a few instructions: commit as you go, don't push, run the tests, check UI changes in the browser, and write the final message as a PR description.
4. **Browser testing**: agents get an in-process MCP server (`mcp__browser__open/click/type/press/screenshot/evaluate/console`) backed by headless Chromium. Every action's screenshot streams to their station's display.
5. **Their own task list**: when an agent keeps a task list with Claude Code's task tools (TodoWrite, or TaskCreate and TaskUpdate), the office follows it from the session's messages (`tasks.ts`), without asking for one or changing how they keep it. It shows under **Tasks** in their panel (a green lamp for done, gold for what they're doing now), on the Tricorder, and on their station's display (see below).
6. **Deliver**: if they left uncommitted changes, they're asked once to commit them. Then the office pushes the branch and opens the PR (`Closes #N`) with the agent's summary as the body. Before the (forced, with lease) push it fetches with `--prune`, so a branch GitHub deleted after an earlier squash merge can't leave a stale ref that makes git refuse. When GitHub answers the push or the PR with a 5xx, it tries again after 4, 8 and 16 seconds, saying so in the agent's terminal, before giving up.
7. **Follow-ups**: message an agent at any time. While they're working, the message reaches them at their next step. Once they're done, the message resumes the same Claude session and the new commits update the PR.
8. **Merge conflicts**: a conflicting PR gets a **Resolve conflicts** button on the board (auto-merge presses it too). The office first merges the base branch in itself, in a scratch worktree (`mergeBase` in `server/agents/workspace.ts`), and pushes the merge when git needs no help, or when every conflicted file has a rule in the repo's `.gitattributes`: `focus-merge=union` keeps both sides' lines (append-only docs), `focus-merge=theirs` takes the base branch's version and `focus-merge=ours` the PR's (generated files: this repo takes main's baked GLBs, so a PR that changes `blender/` itself needs its decks built again, `npm run ship` or the Ship workflow by hand). Files with git's own `merge=union`, like this repo's `CLAUDE.md`, rarely conflict at all, in the office's merges or anyone's. Before pushing, it runs the project's `typecheck` script on the merge, if it has one, in the repo's checks folder: a merge git makes cleanly can still break the tree, and one that does goes to an agent like a conflict. The ledger logs which files conflicted, and whether the office merged it (`office`), settled it by rule (`auto`) or an agent had to (`agent`, with the check that broke, if that's why). Otherwise the agent who opened it merges the base branch in and updates the PR. If nobody in the office owns the PR (a teammate's, or the agent already went home), a new agent sits down on the PR's branch to do it. That new agent works on the model and effort set under **Model and effort for resolving merge conflicts** in the manager's Settings tab (conflicts are usually mechanical, so a cheaper model often does): an empty model means the office's **Model**, and "default effort" the model's own. They're stamped on the agent when it sits down, so it keeps them if its session is resumed after the settings change. The PR's owner resolves conflicts in their own session, on whatever model and effort they already had.
9. **QA**: every PR the office opens or updates goes to the holodeck's QA officer (see [QA](qa.md)).
10. **Merged**: when the PR is merged (from the board or on GitHub), the agent leaves and their worktree is cleaned up.

**An agent's panel** (<kbd>E</kbd> on them or their station) has their terminal on the left (Claude's replies rendered from markdown, with headings, lists, tables and code; so are a helper's transcript and the Tricorder's terminal, while the station displays draw them as plain text without the marks) and, on the right, whichever view its sidebar has picked: their **Browser**, Claude's **Tasks**, and for a goal's lead the **Goal** (what done looks like, this slice, what we learned, what's next, and its pull requests) and the **Crew** of helpers. Each button carries a readout (LIVE, 1/3) and is dimmed while there's nothing to see. It starts on the browser if one's up, otherwise on the first view with something in it; once you pick one it stays put.

**Station displays** show an agent's work in panes side by side: their terminal; their browser, while they have a page up; and their progress, while there's any: the task list Claude keeps for itself, and for a goal's lead the goal note's what-done-looks-like and this slice's checklist. A desk's laptop fits two panes, so the browser wins while it's showing and the task list's count moves to the status bar; a lead's viewscreen in their briefing room (6 m across, nearly wall to wall) fits four, so what the lead has shown or asked and their browser stand side by side between the terminal and the progress pane (on a narrower screen the two share a column, what they've shown over the browser). Each pane of a briefing room's viewscreen opens up close on its own (aim at it and press E, from anywhere in the room): what the lead has shown or asked, their browser, their goal and tasks, or their session; with nobody there, the screen is the station's, as its door is. To choose what the screens show, use the **Panes** strip of switches on the dado under the viewscreen, to starboard (the station's sign is its counterpart to port), at any station, with a lead or free: aim at a switch and press E to turn the lead's artifacts, the browser, the goal note or Claude's task list on or off on every display (the terminal always shows), just for you (your browser remembers them, and every station's strip shows the same).
