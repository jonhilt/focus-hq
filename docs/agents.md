# How an agent works an issue

1. **Hire**: the agent gets a station on the project's holodeck and a name. If the office is at its concurrency limit, they wait in the queue (⏳).
2. **Set up**: `~/.focus/repos/<owner>__<name>` holds one clone per repository. The agent gets a fresh `git worktree` of it on a new branch `focus/<issue>-<slug>-<id>`, so agents never step on each other.
3. **Work**: Claude Code runs in that worktree with the issue (title, body, labels, comments) as its task. It also gets a few instructions: commit as you go, don't push, run the tests, check UI changes in the browser, and write the final message as a PR description.
4. **Browser testing**: agents get an in-process MCP server (`mcp__browser__open/click/type/press/screenshot/evaluate/console`) backed by headless Chromium. Every action's screenshot streams to their station's display.
5. **Their own task list**: when an agent keeps a task list with Claude Code's task tools (TodoWrite, or TaskCreate and TaskUpdate), the office follows it from the session's messages (`tasks.ts`), without asking for one or changing how they keep it. It shows under **Tasks** in their panel (a green lamp for done, gold for what they're doing now), on the Tricorder, and on their station's display (see below).
6. **Deliver**: if they left uncommitted changes, they're asked once to commit them. Then the office pushes the branch and opens the PR (`Closes #N`) with the agent's summary as the body.
7. **Follow-ups**: message an agent at any time. While they're working, the message reaches them at their next step. Once they're done, the message resumes the same Claude session and the new commits update the PR.
8. **Merge conflicts**: a conflicting PR gets a **Resolve conflicts** button on the board. The agent who opened it merges the base branch in and updates the PR. If nobody in the office owns the PR (a teammate's, or the agent already went home), a new agent sits down on the PR's branch to do it.
9. **QA**: every PR the office opens or updates goes to the holodeck's QA officer (see [QA](qa.md)).
10. **Merged**: when the PR is merged (from the board or on GitHub), the agent leaves and their worktree is cleaned up.

**An agent's panel** (<kbd>E</kbd> on them or their station) has their terminal on the left (Claude's replies rendered from markdown, with headings, lists, tables and code; so are a helper's transcript and the Tricorder's terminal, while the station displays draw them as plain text without the marks) and, on the right, whichever view its sidebar has picked: their **Browser**, Claude's **Tasks**, and for a goal's lead the **Goal** (what done looks like, this slice, what we learned, what's next, and its pull requests) and the **Crew** of helpers. Each button carries a readout (LIVE, 1/3) and is dimmed while there's nothing to see. It starts on the browser if one's up, otherwise on the first view with something in it; once you pick one it stays put.

**Station displays** show an agent's work in panes side by side: their terminal; their browser, while they have a page up; and their progress, while there's any: the task list Claude keeps for itself, and for a goal's lead the goal note's what-done-looks-like and this slice's checklist. A desk's laptop fits two panes, so the browser wins while it's showing and the task list's count moves to the status bar; a lead's bigger display fits all three. Press E on a briefing room's big screen (from anywhere in the room) to look at what the lead has shown up close, and to choose what it shows: a picture of the screen whose panes switch the lead's artifacts, the browser, the goal note and Claude's task list on or off on every display, just for you (your browser remembers them).
