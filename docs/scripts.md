# Scripts

Focus installs with pnpm (`corepack enable`, then `pnpm install`).

Focus's own dev tooling lives in `tools/`, apart from the app: the demo ship's start and stop, the smoke, perf, gap and z-fighting scans, the ship's Blender build, the flows recording, the QA catch rate, the bug corpus and replay, the card replay, and the theme shots. None of it runs as part of Focus. A plugin's scripts live in its own folder (`plugins/<id>/scripts/`).

| | |
| --- | --- |
| `pnpm run demo` | demo mode with hot reload |
| `pnpm run demo:start` | a demo ship in the background that outlives the shell that started it: on a free port of its own, it waits until Focus answers and prints its URL, pid, log and data folder (`--built` builds the client first and serves that, so your edits don't reload the page under test). Run it again and it keeps the one that's up. The demo rolls its ids from the same dice each start (`seedShip` in `server/util.ts`), so its projects and goal leads keep their ids across a restart, and a script driving its API can keep the ones it read. Its record, log and data live in the checkout's `.demo/` (gitignored), so every worktree has its own |
| `pnpm run demo:status` | whether this checkout's demo ship is up (exits 0) or not, where, and whether the checkout has moved on from the commit it started on |
| `pnpm run demo:stop` | stops this checkout's demo ship, its whole process group, by the pid in its record: never anything by port or name, so another agent's demo is safe |
| `pnpm run dev` | live mode with hot reload |
| `pnpm run build` | build the client into `dist/` |
| `pnpm start` | serve `dist/` in live mode |
| `pnpm run typecheck` | `tsc` over server, client and shared code, then Effect's language service diagnostics |
| `pnpm run lint` | ESLint |
| `pnpm test` | unit tests (vitest) for the pure decision code: QA verdicts, badges, prompts. Every test rolls the server's random choices (crew names, ids, the demo's picks) from a fixed seed (`vitest.setup.ts`), so a run fails the same way every time; a failing test prints its seed, and `FOCUS_TEST_SEED=<n>` rolls another. A test file that runs real git, or loads Focus's own plugins (`loadPlugins`), sets `vi.setConfig({ testTimeout: 30_000 })`, since a few dozen git commands, or every plugin's import graph, pass vitest's 5 s on a busy machine (`tools/testBudgets.test.ts` holds every such file to it). A test imports its modules at the top of the file, never with `import()` inside an `it` or `test`, where loading and transforming them (fakeFocus's import graph alone) runs on that test's 5 s (the same file checks it); a slow check that's pure computation is made cheaper instead |
| `pnpm run test:repeat` | optional: runs the unit tests 20 times (`--times <n>`), each on the next seed (`--seed <first>`) with files and tests shuffled by it, and stops at the first failure with the command to run it again the same way: tests that pass only on some seeds or in some order show up here, not in an agent's checks. Other arguments go to vitest |
| `pnpm run crap` | [CRAP scores](../plugins/scorecard/crap.md): runs the unit tests with coverage and lists the functions riskiest to change (complexity against coverage); `--changed` adds what the branch touched; `--ratchet` fails when a file gains a function over 30 ([the ratchets](../plugins/scorecard/README.md#the-ratchets)), and `--lower` locks in a file that lost one |
| `pnpm run rules` | how much of each file that keeps state the [state rules](invariants.md#describing-a-part)' checks reach, run alone with coverage on seed 1; `--ratchet` fails a file reached less than its baseline, or a new one no description reaches ([the ratchets](../plugins/scorecard/README.md#the-ratchets)), and `--raise` locks in a gain |
| `pnpm run fence:lower` | [the ratchets](../plugins/scorecard/README.md#the-ratchets): lowers `plugins/scorecard/fence-baseline.json` to each file's type assertions now, after you removed some; it never raises one |
| `pnpm run scorecard` | [the scorecard](../plugins/scorecard/README.md): runs the gate (typecheck, lint, tests with coverage, build), counts the fence (type assertions, `any`, suppressions), how far the server is on Effect, CRAP and Ops' numbers from the ledger, saves it in `~/.focus/plugins/scorecard/` and marks what changed since the last one |
| `pnpm run climb:replay` | optional, by hand (it costs real sessions): tests whether the [climber](../plugins/climber/README.md)'s log of past climbs steers its shortlist, control against treatment, judged by a cheaper model (`--runs`, `--card`) |
| `pnpm run flow` | [where goals' time goes](../plugins/flow/README.md) (a script of the `flow` plugin, run whether it's on or not): every closed goal's lead time split into the lead at work, reworking, and waiting on its background work, QA, a merge or the captain, from its lead's transcript and the ledger, with the biggest wait and the quality guards; `--since`/`--until` to compare before and after a change |
| `pnpm run before-after` | [what agents did before and after a change](../plugins/flow/README.md#before-and-after) (a script of the `flow` plugin): the ledger's 7 days either side of the last CLAUDE.md commit (`--at`, `--days`, `--project`, `--task`), per session: turns, wasted calls, cost, captain corrections and other frictions, QA's pass rate |
| `pnpm run record-flows` | [the cartography plugin](../plugins/cartography/README.md)'s recorded run: a demo ship on a free port with `FOCUS_FLOWS` set, the captain coming aboard with `?flows` and opening the engineering station, its Maps and the ledger while the demo's crew work (120 s, `--seconds <n>`), saved in `.focus/cartography-flows.json`: each event Focus sent over `/ws` against the file that sent it, and each `/api` request against the browser's file that made it. Commit it with the code it was recorded on, and record again when the map says its files are gone |
| `pnpm run qa-catch` | [QA's catch rate](qa-catch.md): plants one known bug in each of the latest merged goal pull requests, in throwaway clones, runs the QA officer's own review on each (once for each configuration in `.focus/benchmarks/qa-catch.yaml`), and counts how many QA caught (about $6–10 a run; `--dry` plants them without reviewing) |
| `pnpm run bug-corpus` | [the bug corpus](bug-corpus.md): for each real fix in `tools/bug-corpus/fixes.txt`, runs the tests it changed on the code just before it and on it, in throwaway worktrees, and writes the ones that fail before and pass after (real bugs with a referee test) to `tools/bug-corpus/corpus.json` (free, about half an hour; `--only <sha>` for one) |
| `pnpm run bug-replay` | [replaying QA on real bugs](bug-corpus.md#replaying-qa): runs the QA officer's own review on each commit the bug corpus traced a real bug to, in throwaway clones, and counts how many it would stop for that very bug (a judge holding the fix's diff decides); `--control` also reviews as many commits no listed bug came from, each review blocks only with proof the replay checks in its clone, as Ops does ([QA → Proof](qa.md#proof)) (about $35 a full run with controls; `--dry` lists them) |
| `pnpm run card-replay` | replays Focus's history in `~/.focus` (the ledger, each goal lead's run journal, `state.json`), read-only and free: every card a lead's finished turn put in front of the captain, the chief of staff's route for it, and how it ended (the captain answered, the chief of staff's words went, or something else woke the lead first and wiped it unanswered), summed up per route with the median wait, then each route 2 or 3 card that was wiped; `--since <days>`, `--project <id>`, `--json <file>` writes every card's timeline |
| `pnpm run jev-backtest` | asks TypeSafe's Jev where each held-out lead turn of the chief of staff's backtest goes (`~/.focus/chief-of-staff/backtest/test.json` and the blind sample), one request a turn, and keeps its raw answers in `backtest/jev-v1-raw.jsonl`; skips turns already answered and stops before $1; `--dry-run` prints one request and the cost, `--limit <n>`; needs `TYPESAFE_API_KEY` ([backtesting Jev](../plugins/chief-of-staff/README.md#backtesting-jev)) |
| `pnpm run jev-sweep` | free and offline: routes those answers at every interrupt bar and prints each bar's score beside Haiku's and Sonnet's runs, then writes one bar's routes for `backtest/score.py`; `--threshold <p>` (0.5), `--captains-call` |
| `pnpm run jev-fresh` | the Jev backtest's check on fresh turns: picks a sample of lead turns the captain answered since `--since` (30, at most 3 a goal), with the live judge's route on each, and writes a labelling page to `~/.focus/chief-of-staff/fresh/`; then `jev-backtest --set fresh` asks Jev about them and `jev-fresh --score` scores both against the captain's labels; read-only on the ledger, free ([backtesting Jev](../plugins/chief-of-staff/README.md#backtesting-jev)) |
| `pnpm run jev-watch` | watches Route with Jev live: each day's chief-of-staff verdicts by who routed them (Jev or Haiku), how many interrupted the captain, and the turns Jev couldn't route; `--days <n>` (7), `--project <id>`; read-only on the ledger, free ([who judges](../plugins/chief-of-staff/README.md#how-it-judges-a-turn)) |
| `pnpm run claude-streams` | records what real Claude Code says down the SDK in three tiny scripted sessions on Haiku (a message mid-turn and one as a turn ends, a workflow and a command at once, Focus's input closed with a command running), keeping only the messages' shapes, never their words, in `data/claude-streams/` (gitignored): the source of the [Claude Code contract](contracts.md#claude-code-the-sdks-stream)'s real sessions. Needs `FOCUS_LIVE_CLAUDE=1` (a few cents a scenario, each stopped past $0.30); name scenarios to run only those. Record again when Claude Code moves on, and distil what changed into `REAL` by hand |
| `pnpm run smoke` | headless Playwright check of the splash screen in demo mode (screenshots in `smoke-shots/`); it waits for the app's ready signal (`window.focusHQ`, set once the ship has loaded and the splash is up), not the page's load |
| `pnpm run perf` | optional, on-demand: walks a busy demo ship on the GPU in headless Chromium, from the bridge into a holodeck's hall and on into a briefing room, twice, and prints each step's frame times, main-thread time, shader programs linked and textures sent to the GPU (the first walk is what walking in for the first time costs, the second what it costs every time) |
| `pnpm run zfight` | optional, on-demand headless scan of the demo ship's 3D scene for z-fighting (coplanar faces from different meshes); fails listing each pair. |
| `pnpm run gaps` | optional, on-demand headless scan of the demo ship's 3D scene for gaps (faces from different meshes facing each other 2 mm to 5 cm apart, like a panel hovering off its wall); fails listing each pair. |
| `pnpm run ship` | rebuilds the decks modelled in Blender (`blender/*.py`, the source: change the script, not the `.blend`) into `client/public/ship/*.glb`, baking each deck's ambient occlusion in Cycles (`blender/bake.py`), and saves a `.blend` of each in `blender/build/`. Needs Blender (`BLENDER`, else on the PATH, else in /Applications or Program Files), but only to change the ship: the GLBs are committed. Commit the GLBs with the script change, or push the script change alone and CI's Ship workflow (`.github/workflows/ship.yml`) builds them and commits them back to the branch a few minutes later, so pull before pushing again |
