# Scripts

Focus installs with pnpm (`corepack enable`, then `pnpm install`).

| | |
| --- | --- |
| `pnpm run demo` | demo mode with hot reload |
| `pnpm run demo:start` | a demo office in the background that outlives the shell that started it: on a free port of its own, it waits until the office answers and prints its URL, pid, log and data folder (`--built` builds the client first and serves that, so your edits don't reload the page under test). Run it again and it keeps the one that's up. The demo rolls its ids from the same dice each start (`seedOffice` in `server/util.ts`), so its projects and goal leads keep their ids across a restart, and a script driving its API can keep the ones it read. Its record, log and data live in the checkout's `.demo/` (gitignored), so every worktree has its own |
| `pnpm run demo:status` | whether this checkout's demo office is up (exits 0) or not, where, and whether the checkout has moved on from the commit it started on |
| `pnpm run demo:stop` | stops this checkout's demo office, its whole process group, by the pid in its record: never anything by port or name, so another agent's demo is safe |
| `pnpm run dev` | live mode with hot reload |
| `pnpm run build` | build the client into `dist/` |
| `pnpm start` | serve `dist/` in live mode |
| `pnpm run typecheck` | `tsc` over server, client and shared code |
| `pnpm test` | unit tests (vitest) for the pure decision code: QA verdicts, badges, prompts. Every test rolls the server's random choices (crew names, ids, the demo's picks) from a fixed seed (`vitest.setup.ts`), so a run fails the same way every time; a failing test prints its seed, and `FOCUS_TEST_SEED=<n>` rolls another. A test file that runs real git, or loads the office's own plugins (`loadPlugins`), sets `vi.setConfig({ testTimeout: 30_000 })`, since a few dozen git commands, or every plugin's import graph, pass vitest's 5 s on a busy machine (`scripts/testBudgets.test.ts` holds every such file to it); a slow check that's pure computation is made cheaper instead |
| `pnpm run test:repeat` | optional: runs the unit tests 20 times (`--times <n>`), each on the next seed (`--seed <first>`) with files and tests shuffled by it, and stops at the first failure with the command to run it again the same way: tests that pass only on some seeds or in some order show up here, not in an agent's checks. Other arguments go to vitest |
| `pnpm run crap` | [CRAP scores](../plugins/scorecard/crap.md): runs the unit tests with coverage and lists the functions riskiest to change (complexity against coverage); `--changed` adds what the branch touched |
| `pnpm run scorecard` | [the scorecard](../plugins/scorecard/README.md): runs the gate (typecheck, lint, tests with coverage, build), counts the fence (type assertions, `any`, suppressions), how far the server is on Effect, CRAP and the office's numbers from the ledger, saves it in `~/.focus/plugins/scorecard/` and marks what changed since the last one |
| `pnpm run flow` | [where goals' time goes](../plugins/flow/README.md) (a script of the `flow` plugin, run whether it's on or not): every closed goal's lead time split into the lead at work, reworking, and waiting on its background work, QA, a merge or the captain, from its lead's transcript and the ledger, with the biggest wait and the quality guards; `--since`/`--until` to compare before and after a change |
| `pnpm run before-after` | [what agents did before and after a change](../plugins/flow/README.md#before-and-after) (a script of the `flow` plugin): the ledger's 7 days either side of the last CLAUDE.md commit (`--at`, `--days`, `--project`, `--task`), per session: turns, wasted calls, cost, captain corrections and other frictions, QA's pass rate |
| `pnpm run record-flows` | [the cartography plugin](../plugins/cartography/README.md)'s recorded run: a demo office on a free port with `FOCUS_FLOWS` set, the captain coming aboard with `?flows` and opening the engineering station, its Maps, the ledger and comms while the demo's crew work (120 s, `--seconds <n>`), saved in `.focus/cartography-flows.json`: each event the office sent over `/ws` against the file that sent it, and each `/api` request against the browser's file that made it. Commit it with the code it was recorded on, and record again when the map says its files are gone |
| `pnpm run qa-catch` | [QA's catch rate](qa-catch.md): plants one known bug in each of 10 recently merged goal pull requests, in throwaway clones, runs the QA officer's own review on each, and counts how many QA caught (about $6–10 a run; `--dry` plants them without reviewing) |
| `pnpm run smoke` | headless Playwright check of the splash screen in demo mode (screenshots in `smoke-shots/`); it waits for the app's ready signal (`window.focusHQ`, set once the ship has loaded and the splash is up), not the page's load |
| `pnpm run perf` | optional, on-demand: walks a busy demo office on the GPU in headless Chromium, from the bridge into a holodeck's hall and on into a briefing room, twice, and prints each step's frame times, main-thread time, shader programs linked and textures sent to the GPU (the first walk is what walking in for the first time costs, the second what it costs every time) |
| `pnpm run studio <scene>` | films a scene script (`scenes/*.yaml`) against a demo office: a 1080p rough cut and a beat sheet in `studio-out/<scene>/`; `--voice <file>` mixes a voiceover into `final.mp4` ([the TV studio](studio.md)) |
| `pnpm run zfight` | optional, on-demand headless scan of the demo office's 3D scene for z-fighting (coplanar faces from different meshes); fails listing each pair. |
| `pnpm run gaps` | optional, on-demand headless scan of the demo office's 3D scene for gaps (faces from different meshes facing each other 2 mm to 5 cm apart, like a panel hovering off its wall); fails listing each pair. |
| `pnpm run ship` | rebuilds the decks modelled in Blender (`blender/*.py`, the source: change the script, not the `.blend`) into `client/public/ship/*.glb`, baking each deck's ambient occlusion in Cycles (`blender/bake.py`), and saves a `.blend` of each in `blender/build/`. Needs Blender (on the PATH, in /Applications or Program Files, or `BLENDER`), but only to change the ship: the GLBs are committed. Commit the GLBs with the script change, or push the script change alone and CI's Ship workflow (`.github/workflows/ship.yml`) builds them and commits them back to the branch a few minutes later, so pull before pushing again |
