# Cloud agents

The **local / cloud** picker next to the effort picker (on **Assign agent**, and at the New issue stand) puts an agent in a [Claude Code cloud session](https://code.claude.com/docs/en/claude-code-on-the-web) instead of on your machine, and **☁ Move to cloud** moves a local agent there partway through. They still get a station, and the office still opens the PR and hands it to QA.

- **How it runs:** through the Agent SDK's bundled CLI with `--cloud`, which starts the cloud session and relays it in the same message stream as a local agent, so their terminal is live as usual. The laptop panel links to the session on claude.ai (**Cloud session ↗**), where you can watch or steer it too.
- **When Claude Code won't start one:** the CLI starts a new cloud session without a terminal only while Anthropic has its headless cloud client switched on for your account, a server-side rollout with no flag or SDK option to request it. Otherwise it refuses ("--cloud requires an interactive terminal"), and the agent waits for you to start the session (see **Starting the session** below), with their hand up and a ☁ bar on their laptop. **Keep local** there makes them a local agent instead, starting their task in the worktree the office already set up.
- **Their branch:** the office publishes `focus/<issue>-<slug>-<id>` to GitHub first (the cloud session clones it from there), and the agent is told to commit and push to that branch, and only that one, with `git push origin HEAD:<branch>`. When the session ends, the office fetches the branch and opens the PR. If nothing new arrived, the agent is asked once to push.
- **Screenshots:** the office's browser tool runs on your machine, so cloud agents test in the cloud machine's own browser instead (a Playwright script, say). Any screenshot they look at comes back in their tool results and shows on their station's display, like a local agent's browser.
- **Follow-ups** reattach to the same cloud session (`--cloud <session id>`). If that fails (an archived session, say), a new cloud session picks the work up from the branch with your message. If Claude Code refuses to start that one, the office fetches the branch into the worktree first, so nothing the cloud session pushed is lost, and the agent carries on locally with your message.
- **Stop** interrupts the cloud session's turn before letting go of it.
- The QA officer always works locally: QA needs the office browser for its screenshots. So do goals' leads, and agents resolving merge conflicts.
- **Smoke test:** to check cloud sessions work on your account, assign a cloud agent to a small docs-only issue and confirm that a PR opens from its `focus/…` branch.

You need a claude.ai login (not `FOCUS_USE_API_KEY`) and GitHub connected for cloud sessions: install the [Claude GitHub App](https://github.com/apps/claude) on the repo, or run `/web-setup` in Claude Code. Without the app, the CLI uploads the worktree instead of cloning. On Team and Enterprise plans, an admin has to allow cloud sessions. Cloud agents count towards **Agents working at once**: they share your plan's limits. The cloud session works in your [cloud environment](https://code.claude.com/docs/en/cloud-environments) (network access, setup script), not with your local tools. The headless `--cloud` mode the office drives isn't documented by Anthropic yet, so a Claude Code update can change how it behaves.

## Starting the session

Joining a cloud session that already exists works without a terminal on every account; only starting a new one needs one. So when the office can't start an agent's session, you do, and the office joins it:

- **▶ Start in a terminal** opens a terminal on this machine, in the agent's worktree, running the Agent SDK's bundled `claude --cloud` with a short first message ("Focus sends the task in its next message… reply only with the word Ready"). On macOS and Linux the office records the terminal with `script` and spots the session's id as soon as Claude Code shows it, then joins the session and sends the office's instructions with the work. You can watch in the terminal, on claude.ai, or on the laptop as usual. If Claude Code asks you something first (whether to trust the folder, say), answer it there. If the session is still answering that first message when the office joins, the office tries again every 15 seconds.
- **…or paste a claude.ai/code session link**: start a session yourself (on claude.ai/code, or with `claude --cloud` in any terminal) and paste its link or id. Windows terminals aren't recorded, so there you paste the link once the terminal shows it.
- Which terminal: on macOS the script is a `.command` file that `open` hands to Terminal (or whatever opens `.command` files); on Linux the office tries `x-terminal-emulator`, `gnome-terminal`, `konsole`, `xfce4-terminal`, `kitty`, `alacritty`, `wezterm` and `xterm` in turn; on Windows, `cmd`. Set `FOCUS_TERMINAL` (e.g. `kitty -e`) to use your own, and the script's path goes after it. The scripts and recordings are in `~/.focus/cloud-terminals/`.
- If the office can't join the session (a wrong link, say), the agent goes back to waiting, and their terminal says why.

## Moving an agent to the cloud

**☁ Move to cloud** on a local developer's laptop (for an issue or a QA fix) moves them there partway through: whatever they're doing stops, everything in their worktree is committed (a WIP commit if needed) and pushed to their branch, and they wait for a cloud session, which you start as above. The new session reads the issue and `git log` to catch up, and carries on from the branch: the conversation itself doesn't move, the work does. Messages you send meanwhile wait for the cloud session. **Keep local** (or **Stop**) instead takes them back to their own conversation on this machine, stopped until you message them. Claude Code's own `/teleport` can move a conversation to the cloud, but only from an interactive terminal, behind its own rollout, and only for a session connected to Remote Control, so the office moves the work through the branch instead.
